Deployment guide · v1.1.0

Deploy SRE Agent on Ubuntu, Debian or RHEL

Install the .deb or .rpm package on one Linux server and run it as a background service with systemd or pm2. This guide covers a new install and an upgrade of an older version.

~15 min total2 min install5 min questionsrest: checks

Which path are you on?

New installSRE Agent is not on this server yet. Follow steps 0 to 7 in order (about 15 minutes). UpgradeYou already run 2.0.x or 2.1.x. Go to “Upgrade an existing install” (about 5 minutes). Your settings and data are kept.

Not sure? Run sre-agent version. If it prints a version, you are upgrading. If the command is not found, it is a new install.

Check your log format first

The agent raises incidents only for lines it can read. Each error line must use one of these formats:

FormatExample line
Bracketed[2026-10-27T10:00:00Z] [ERROR] [orders-api] DatabaseTimeout: connection refused
JSON lines (e.g. winston){"level":"error","message":"PaymentFailed: gateway 502","service":"orders-api","timestamp":"2026-10-27T10:00:05Z"}
Node logger style2026-10-27 10:00:01:184 [error] Error fetching report metrics: fetch failed
  • ERROR, FATAL, CRITICAL become high severity; WARN becomes medium. INFO and DEBUG are ignored.
  • Raw stack traces never raise an incident on their own. They are attached as context when a proper error line fires.
  • JSON loggers must write level as text ("error"). Pino's numeric levels ("level":50) are not recognised; configure pino to print labels.
  • pm2 users: the pm2 logs error file holds whatever your app prints. If it uses plain console.error, switch to a structured logger (winston JSON is easiest) or the bracketed format.

1Install the package

wget https://github.com/AA-Solutions-tech/SRE-Agent/releases/download/v1.1.0/sre-agent_1.1.0-1_amd64.deb
wget https://github.com/AA-Solutions-tech/SRE-Agent/releases/download/v1.1.0/SHA256SUMS
sha256sum -c --ignore-missing SHA256SUMS          # expect: sre-agent_1.1.0-1_amd64.deb: OK
sudo apt install ./sre-agent_1.1.0-1_amd64.deb

What these commands do: the first downloads the package, the second downloads the list of expected checksums, the third checks that your download is not corrupted or tampered with (it must print OK), and the fourth installs it. apt install ./file.deb (with the ./) also pulls in the one dependency, git. The package carries its own Python, so nothing else is installed on your system.

You should see this at the end:

sre-agent: created /etc/sre-agent/sre-agent.env

SRE Agent 1.1.0 installed. The service is enabled but NOT started yet.
  Configure it:   sudo sre-agent setup

Everything is installed under /opt/sre-agent. Your settings go to /etc/sre-agent/sre-agent.env and data (database, SSH key, repo clone) to /var/lib/sre-agent, so a later upgrade never touches them.

RHEL, Rocky, Alma, Amazon Linux

Use the .rpm instead (install acl with dnf in step 3). On arm64 use sre-agent_1.1.0-1_arm64.deb or sre-agent-1.1.0-1.aarch64.rpm.

sudo dnf install https://github.com/AA-Solutions-tech/SRE-Agent/releases/download/v1.1.0/sre-agent-1.1.0-1.x86_64.rpm

Verify the install

sre-agent version                     # sre-agent 1.1.0
id sre-agent                          # the service user exists
sudo ls -l /etc/sre-agent/            # sre-agent.env  -rw-r----- root sre-agent

The install put the program in /opt/sre-agent, created the sre-agent system user, wrote the config file with a unique API key and approval secret for this server, and registered the sre-agent systemd service (enabled, not started).

3Let the agent read your log file

Same-server logs only. Skip this step if the log is on another server (SSH). The agent runs as the sre-agent user, which must be able to read the log file and open its folders.

Logs under /var/log/... (most common)

sudo apt install -y acl
sudo setfacl -m u:sre-agent:rx /var/log/orders-api                 # open the folder
sudo setfacl -m u:sre-agent:r /var/log/orders-api/error.log        # read the file
sudo setfacl -d -m u:sre-agent:r /var/log/orders-api               # new/rotated files too
sudo -u sre-agent head -1 /var/log/orders-api/error.log            # must print a line, not "Permission denied"

pm2 logs under a home folder

For example /home/deploy/.pm2/logs/orders-api-error.log:

sudo apt install -y acl
sudo setfacl -m u:sre-agent:x /home/deploy /home/deploy/.pm2       # pass through only
sudo setfacl -m u:sre-agent:rx /home/deploy/.pm2/logs
sudo setfacl -m u:sre-agent:r /home/deploy/.pm2/logs/orders-api-error.log
sudo setfacl -d -m u:sre-agent:r /home/deploy/.pm2/logs
sudo -u sre-agent head -1 /home/deploy/.pm2/logs/orders-api-error.log

If you run the agent with systemd and the log is under /home, let the service see /home (it hides home folders by default):

sudo systemctl edit sre-agent

Add these lines in the editor, then save:

[Service]
ProtectHome=read-only

New in 2.1: sudo sre-agent doctor checks every watched file and, if one cannot be read, prints the exact setfacl and ProtectHome commands to fix it.

For SSH, the setup then asks three more things:

  • Connect to 10.0.1.25:22 now to trust its host key? [Y/n]: press Enter.

sudo -u logreader mkdir -p ~logreader/.ssh

5Start it

5A · With systemd

sudo systemctl start sre-agent          # skip if setup already started it
sudo systemctl status sre-agent         # Active: active (running)

It starts automatically at boot (the package enabled it).

5B · With pm2

pm2 must run the agent as root; the agent then switches itself to the sre-agent user. This is root's own pm2 list, separate from your app user's list.

sudo systemctl disable --now sre-agent                                   # make sure systemd does not run it too
sudo pm2 start /usr/bin/sre-agent --name sre-agent --interpreter none -- serve
sudo pm2 save                                                            # remember it
sudo pm2 startup systemd                                                 # start root's pm2 at boot (once per server)
sudo pm2 list                                                            # sre-agent  online

If sudo pm2 says “command not found” (pm2 installed with nvm), pass your PATH. Do the same for save, startup and list:

sudo env "PATH=$PATH" pm2 start /usr/bin/sre-agent --name sre-agent --interpreter none -- serve

6Verify everything works

Run these in order. Each comment says what you should see.

# 1. Health check: all required checks OK
sudo sre-agent doctor

# 2. Process is running as the sre-agent user
ps -o user=,cmd= -C python3 | grep sre_agent      # sre-agent  ... -m sre_agent serve

# 3. Web API answers
curl -s localhost:8000/health                      # {"ok":true,"version":"1.1.0",...}

# 4. API is protected
curl -s -o /dev/null -w "%{http_code}\n" localhost:8000/issues                              # 401
KEY=$(sudo sed -n 's/^SRE_API_KEY=\([^ ]*\).*/\1/p' /etc/sre-agent/sre-agent.env)
curl -s -o /dev/null -w "%{http_code}\n" -H "X-API-Key: $KEY" localhost:8000/issues         # 200

# 5. The watcher started
sudo grep -m1 "auto mode ON" /var/log/sre-agent/sre.log          # a line with "auto.01.start"

End-to-end test: make a test incident

Write one test error line into the watched log (for SSH, run it on the log server). Use your service name and log path:

echo "[$(date -u +%Y-%m-%dT%H:%M:%SZ)] [ERROR] [orders-api] SreAgentTest: this is a test error, please ignore" \
  | sudo tee -a /var/log/orders-api/error.log

Within a few seconds:

curl -s -H "X-API-Key: $KEY" localhost:8000/issues | head -c 400
# {"issues":[{"id":"...","service":"orders-api","error":"SreAgentTest","severity":"HIGH","state":"open","count":1,...

An incident card arrives in Slack / Google Chat / email with the root-cause summary and Approve / Reject / Request changes buttons. Click Reject for the test. If the issue appears but no message arrives, see Troubleshooting.

Upgrade an existing install

For servers already running 2.0.x or 2.1.x. Installing the new package on top of the old one keeps your settings, your data and your SSH key.

What the package does for youIt stops the running service, saves a copy of the database to /var/lib/sre-agent/backups/ (the 5 newest are kept), replaces the program files, leaves /etc/sre-agent/sre-agent.env exactly as it is, and starts the service again if it was running. The database is upgraded the first time the new version starts.

U1 · Check what you run now

sre-agent version                  # e.g. sre-agent 2.0.0
sudo systemctl is-active sre-agent # active, or use: sudo pm2 list

Tells you which version you are leaving and whether it is run by systemd or pm2, which decides the restart in step U3.

U2 · Make a safety copy (optional, 10 seconds)

sudo tar czf ~/sre-agent-backup-$(date +%F).tgz /etc/sre-agent /var/lib/sre-agent

The package already backs up the database, but this also saves your settings and SSH key, so you can restore everything by hand if you ever need to.

U3 · Answer or finish open approval cards first

Approval links and buttons sent by an older version stop working after the upgrade (links are now tied to one action and expire after 7 days). Approve or reject pending cards before upgrading. If you forget, the issue sends a fresh card the next time the error happens.

U4 · Download and verify the new package

VERSION=1.1.0
wget https://github.com/AA-Solutions-tech/SRE-Agent/releases/download/v$VERSION/sre-agent_$VERSION-1_amd64.deb
wget https://github.com/AA-Solutions-tech/SRE-Agent/releases/download/v$VERSION/SHA256SUMS
sha256sum -c --ignore-missing SHA256SUMS          # expect: sre-agent_1.1.0-1_amd64.deb: OK

Use _arm64.deb on an ARM server. Do not install a file whose checksum line does not say OK.

U5 · Install it

# Ubuntu / Debian
sudo apt install ./sre-agent_$VERSION-1_amd64.deb

# RHEL / Rocky / Alma / Amazon Linux
sudo dnf upgrade https://github.com/AA-Solutions-tech/SRE-Agent/releases/download/v$VERSION/sre-agent-$VERSION-1.x86_64.rpm

You should see sre-agent: database backed up to /var/lib/sre-agent/backups/.... Because the file is installed on top of the old one, this is an upgrade, not a fresh install, and the setup wizard is not run again.

If you run it with pm2 the package cannot restart it for you:

sudo pm2 restart sre-agent

U6 · Check the result

sre-agent version                    # sre-agent 1.1.0
sudo sre-agent doctor                # every required line OK; read any WARN
sudo systemctl status sre-agent      # active (running)
curl -s localhost:8000/health        # {"ok":true,"version":"1.1.0",...}

doctor has new checks in 2.2: it makes one tiny live call to your AI model (so a wrong key, model or parameter is reported at once), tests that every watched log can be read, and warns if the approval-link address is localhost. Fix any WARN/FAIL it explains.

U7 · Prove monitoring still works

Repeat the test from Step 6: write one test error line to the watched log. An issue and a card should arrive within seconds. Reject the test card.

Roll back

sudo apt install --allow-downgrades ./sre-agent_-1_amd64.deb       # the old package file
sudo systemctl stop sre-agent
ls /var/lib/sre-agent/backups/                                          # starter.db.<old-version>.<time>
sudo -u sre-agent cp /var/lib/sre-agent/backups/starter.db.2.0.0.<time> /var/lib/sre-agent/starter.db
sudo systemctl start sre-agent

Needed only if something goes wrong. Restoring the database copy puts back the exact data from before the upgrade (issues recorded since then are lost). Downloads of every version stay on the Releases page.

No automatic updatesThese packages are not in an apt or dnf repository, so apt upgrade will not find a new version. Download and install each release yourself, as above.
